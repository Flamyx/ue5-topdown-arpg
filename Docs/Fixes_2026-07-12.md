# C++ Fixes — 2026-07-12

Recap of all code changes made during the multiplayer-crash / meteorite session.
All changes are C++ only (no Blueprints or data assets were modified) and were
compiled into the running editor via Live Coding. **Live Coding patches do not
survive an editor restart — do a normal build (Development Editor | Win64)
before the next session.**

---

## 1. Network bitstream corruption in `FAuraGameplayEffectContext::NetSerialize`

**File:** `Source/Aura/Private/AuraAbilityTypes.cpp`

This was the primary cause of the "crash as client or server when using
abilities" from the 5.7 project. Two independent bugs, both producing archive
misalignment (reader and writer disagree on what bytes mean → everything after
the bad field is read as garbage → crash or corrupted state on the remote side).
The context is serialized on every damage hit (it rides along `FGameplayEffectSpec`,
including the `ClientEffectApplied` RPC), so this fired constantly.

### 1a. Bit count mismatch

13 bits are used (0..12, bit 12 = `KnockbackImpulse`), but only 12 were declared.
The writer's local `RepBits` still had bit 12 set, so it *wrote* the knockback
vector — but the reader's `RepBits` came from the archive with only 12 bits, so
it *never read* it. Knockback is non-zero on nearly every hit.

```cpp
// BEFORE
Ar.SerializeBits(&RepBits, 12);

// AFTER
// 13 bits are in use (0..12) — the count here must match or the archive
// misaligns and every field after it is read as garbage on the remote side
Ar.SerializeBits(&RepBits, 13);
```

### 1b. Asymmetric DamageType serialization in the debuff branch

`DamageType->NetSerialize` was nested inside `if (Ar.IsLoading())` — the reader
consumed a tag the writer never wrote. Triggered whenever a debuff procced.

```cpp
// BEFORE
if (RepBits & (1 << 9))
{
    Ar << bIsSuccessfulDebuff;
    Ar << DebuffDuration;
    Ar << DebuffFrequency;
    Ar << DebuffDamage;

    if (Ar.IsLoading())
    {
        if (!DamageType.IsValid())
        {
            DamageType = TSharedPtr<FGameplayTag>(new FGameplayTag());
        }
        DamageType->NetSerialize(Ar, Map, bOutSuccess);   // reader-only!
    }
}

// AFTER
if (RepBits & (1 << 9))
{
    Ar << bIsSuccessfulDebuff;
    Ar << DebuffDuration;
    Ar << DebuffFrequency;
    Ar << DebuffDamage;

    // Must serialize in BOTH directions — if only the reader consumes the tag
    // the bitstream misaligns and the remote side crashes/corrupts
    if (!DamageType.IsValid())
    {
        DamageType = TSharedPtr<FGameplayTag>(new FGameplayTag());
    }
    DamageType->NetSerialize(Ar, Map, bOutSuccess);
}
```

### 1c. `GetDamageType()` null-deref guard

**File:** `Source/Aura/Public/AuraAbilityTypes.h`

The shared pointer is only allocated when a debuff was rolled (or after
replication of the debuff branch). Any call on a non-debuff context dereferenced
a null `TSharedPtr`.

```cpp
// BEFORE
FGameplayTag GetDamageType() const { return *DamageType; }

// AFTER
FGameplayTag GetDamageType() const { return DamageType.IsValid() ? *DamageType : FGameplayTag(); }
```

## 2. Client-side null crash in projectile overlap handlers

`FAuraDamageEffectParams` is a plain (non-replicated) property on the projectile.
On client machines it is default-constructed, so `DamageEffectParams.SourceASC`
is **null** — and both overlap handlers dereferenced it unconditionally. Any
projectile overlap on a client was a guaranteed crash.

The fix has two halves:

### 2a. Spawn projectiles with the avatar pawn as Instigator

**Files:** `AuraProjectileSpell.cpp`, `FireBolt.cpp`, `MeteoriteProjectileSpell.cpp`

`AActor::Instigator` replicates, so clients can use it for self/friend checks.
The old code passed `Cast<APawn>(GetOwningActorFromActorInfo())` — for players
the owning actor is the **PlayerState**, so that cast silently returned null
even on the server.

```cpp
// BEFORE
GetWorld()->SpawnActorDeferred<AAuraProjectile>(ProjectileClass, SpawnTransform,
    GetOwningActorFromActorInfo(), Cast<APawn>(GetOwningActorFromActorInfo()),  // null for players!
    ESpawnActorCollisionHandlingMethod::AlwaysSpawn);

// AFTER
GetWorld()->SpawnActorDeferred<AAuraProjectile>(ProjectileClass, SpawnTransform,
    GetOwningActorFromActorInfo(), Cast<APawn>(GetAvatarActorFromActorInfo()),  // avatar pawn, replicates
    ESpawnActorCollisionHandlingMethod::AlwaysSpawn);
```

### 2b. Use `GetInstigator()` in the overlap checks; touch `SourceASC` only on the authority

**File:** `Source/Aura/Private/Actor/AuraProjectile.cpp`

```cpp
// BEFORE
auto SourceActor = DamageEffectParams.SourceASC->GetAvatarActor();   // null deref on clients
if (SourceActor == OtherActor) return;
if (!UAuraAbilitySystemLibrary::IsNotFriend(SourceActor, OtherActor)) return;

// AFTER
// Instigator replicates, so this check works on clients too; DamageEffectParams
// does NOT replicate — SourceASC is only safe to touch on the authority below
AActor* SourceActor = GetInstigator();
if (SourceActor == OtherActor) return;
if (SourceActor && !UAuraAbilitySystemLibrary::IsNotFriend(SourceActor, OtherActor)) return;
```

and the damage application (already inside `HasAuthority()`) is additionally
guarded:

```cpp
if (IsValid(DamageEffectParams.SourceASC))
{
    UAuraAbilitySystemLibrary::ApplyDamageEffect(DamageEffectParams);
}
```

### 2c. Same fix in `AMeteoriteProjectile::OnOverlap` + unreachable damage block

**File:** `Source/Aura/Private/Actor/MeteoriteProjectile.cpp`

Besides the same `SourceASC` crash, there was a logic bug: `OnHit()` sets
`bHit = true`, and the server damage block checked `!bHit` *afterwards* — so it
was unreachable and **the meteorite never dealt damage**.

```cpp
// BEFORE
auto Avatar = DamageEffectParams.SourceASC->GetAvatarActor();        // null deref on clients
...
if (!bHit)
    OnHit();                                                          // sets bHit = true

if (HasAuthority() && !bHit)                                          // never true after OnHit()!
{
    ... apply blast damage, Destroy() ...
}

// AFTER
AActor* Avatar = GetInstigator();                                     // replicates
...
const bool bFirstHit = !bHit;
if (bFirstHit)
    OnHit();

if (HasAuthority() && bFirstHit && IsValid(DamageEffectParams.SourceASC))
{
    ... apply blast damage, Destroy() ...
}
```

## 3. Meteorite spawn — now lands on the clicked point (revised 2026-07-13)

**Files:** `Source/Aura/Private/AbilitySystem/GameplayAbility/MeteoriteProjectileSpell.cpp`,
`Source/Aura/Private/Actor/MeteoriteProjectile.cpp`

Why it missed: the meteor **was** aimed straight at the click point, but it
flies at only 400 cm/s and had `ProjectileGravityScale = 0.1`. Gravity pulls it
below the straight aim line for the whole (long) flight, so it always landed
short — between you and the click point. The old spawn also used an
**absolute** world Z (`Z = SpawnHeight`), which breaks on elevated terrain.

Final fix (per request, the meteor spawns above **Aura** again):
- Spawn stays above the caster, with `SpawnHeight` now relative to the
  caster's Z instead of an absolute world height.
- `ProjectileGravityScale` set to `0` on `AMeteoriteProjectile`, so the
  straight-line aim at the target is exact. It still descends visually because
  it starts `SpawnHeight` above you and flies down at an angle.

```cpp
// BEFORE (missed short)
const FVector SpawnLocation = { ActorLocation[0] - SpawnOffset[0],
                                ActorLocation[1] - SpawnOffset[1],
                                SpawnHeight };                        // absolute Z
// gravity 0.1 bent the direct-aim trajectory short

// AFTER
const FVector SpawnLocation = ActorLocation + FVector(-SpawnOffset.X, -SpawnOffset.Y, SpawnHeight);
FRotator Rotation = (ProjectileTargetLocation - SpawnLocation).Rotation();
// MeteoriteProjectile.cpp:
ProjectileMovement->ProjectileGravityScale = 0.f;   // was 0.1f
```

> Check `BP_MeteoriteProjectile` in the editor: if its ProjectileMovement has
> a gravity-scale override saved, the Blueprint value wins over the new C++
> default and must be zeroed there too. If you want a *curved* arc back, the
> aim would need a ballistic solve (`SuggestProjectileVelocity`) — but
> `MaxSpeed = 500` clamps velocity mid-flight, which invalidates that math, so
> straight-line + zero gravity is the reliable option with this setup.

Also added a null check after the deferred spawn:

```cpp
if (Projectile == nullptr) return;
```

## 5. Defensive null guards on the damage path

Places where a dead/disconnected source or a non-Character avatar crashed the
**server**:

**`AuraAbilitySystemLibrary.cpp` — `IsNotFriend`** (called from every overlap):

```cpp
if (!IsValid(FirstActor) || !IsValid(SecondActor)) return false;   // "friend" = no damage, safe default
```

**`AuraAttributeSet.cpp` — `ShowFloatingText`** (source may be gone when a
projectile lands after its caster died/left):

```cpp
// BEFORE
if (AAuraPlayerController* PC = Cast<AAuraPlayerController>(Props.SourceCharacter->Controller))

// AFTER
if (!IsValid(Props.TargetCharacter)) return;
...
if (AAuraPlayerController* PC = IsValid(Props.SourceCharacter)
        ? Cast<AAuraPlayerController>(Props.SourceCharacter->Controller) : nullptr)
```

**`AuraAttributeSet.cpp` — `HandleIncomingXP` and `PostGameplayEffectExecute`:**

```cpp
if (IsValid(Props.SourceCharacter) && Props.SourceCharacter->Implements<UCombatInterface>() && ...)
if (IsValid(Props.TargetCharacter) && Props.TargetCharacter->Implements<UCombatInterface>() && ...)
```

**`ExecCalc_Damage.cpp` — `Execute_Implementation`:**

```cpp
if (IsValid(SourceAvatar) && SourceAvatar->Implements<UCombatInterface>()) ...
if (IsValid(TargetAvatar) && TargetAvatar->Implements<UCombatInterface>()) ...
```

## 6. Log spam fix in `UExecCalc_Damage::DetermineBaseDamage`

**File:** `Source/Aura/Private/AbilitySystem/ExecCalc/ExecCalc_Damage.cpp`

Every damage application logged three
`FGameplayEffectSpec::GetMagnitude called ... when magnitude had not yet been
set by caller` errors, because the calc queries all four damage types but each
spell only sets one.

```cpp
// BEFORE
float DamageTypeValue = Spec.GetSetByCallerMagnitude(DamageTypeTag);

// AFTER — missing lookups are legitimate, don't warn, default to 0
float DamageTypeValue = Spec.GetSetByCallerMagnitude(DamageTypeTag, false, 0.f);
```

## Round 2 — 2026-07-13 (follow-up fixes)

All items from the old "not changed" table were applied — C++ (§7–§12) and
Blueprint (§13) — except the dynamic debuff GE (kept as-is per decision: tag
replication is all that's needed).

### 7. Burn Niagara now stops and is destroyed on death

**Files:** `CombatInterface.h`, `AuraCharacterBase.h/.cpp`, `DebuffNiagaraComponent.cpp`

Root cause: `GetOnDeathDelegate()` / `GetOnASCRegisteredDelegate()` returned the
delegates **by value**. `UDebuffNiagaraComponent` bound its handlers to a
temporary copy, so `OnDeathDelegate.Broadcast()` in `MulticastHandleDeath` never
reached it — the burn flames kept playing on the corpse. (The by-value bug also
silently broke the ASC-registered lambda used when the ASC isn't ready at
component BeginPlay — the player path.)

```cpp
// BEFORE (interface + base class)
virtual FOnDeath GetOnDeathDelegate() = 0;              // returns a COPY

// AFTER
virtual FOnDeath& GetOnDeathDelegate() = 0;             // callers bind the real delegate

// DebuffNiagaraComponent::OnOwnerDeath — also destroy, not just stop emitting
Deactivate();
DestroyComponent();
```

### 8. `CauseDamage` uses the real ability level (+ null guards)

```cpp
// BEFORE
MakeOutgoingGameplayEffectSpec(DamageEffectClass, 1);
// ...Spec dereferenced even if null, target ASC never checked

// AFTER
MakeOutgoingGameplayEffectSpec(DamageEffectClass, GetAbilityLevel());
if (Spec == nullptr || TargetASC == nullptr) return;
```

### 9. FireBolt spread math fixed (`GetEvenlyScacedRotators`)

A level-1 FireBolt flew off to the **left by Spread/2** (i=0 returned the left
edge), and multi-bolt fans were compressed/skewed by stepping `Spread/N`
instead of `Spread/(N-1)`:

```cpp
if (NumProjectiles <= 1) { Ret.Add(Forward.Rotation()); return Ret; }   // straight shot
const float DeltaSpread = Spread / (NumProjectiles - 1);                // edges included
```

`FireBolt.cpp` also lost its unused `LeftOfSpread`/`DeltaSpread` (div-by-zero at
level 1) and duplicate `EffectiveNumProjectiles`, gained a null check on the
spawned bolt, and the fake homing-target `USceneComponent` is now outered to
the projectile so GC can't collect it mid-flight.

### 10. `TargetDataUnderMouse` no longer hangs the ability

Clicking where the cursor trace hits nothing early-returned **without sending
target data**, so the server-side task waited forever and the ability never
ended (input slot dead until respawn). Now the hit result is always sent (and
the PlayerController is null-checked); receivers should check `bBlockingHit`.

### 11. `ClientEffectApplied` RPC slimmed

The server sent a full serialized `FGameplayEffectSpec` to the owning client on
**every** effect application. The server now extracts the asset tags and RPCs
only a `FGameplayTagContainer`, and skips the RPC entirely when there are no
tags:

```cpp
// server-side listener (bound to OnGameplayEffectAppliedDelegateToSelf)
void EffectApplied(...) { Spec.GetAllAssetTags(Tags); if (Tags.Num() > 0) ClientEffectApplied(Tags); }

UFUNCTION(Client, Reliable)
void ClientEffectApplied(const FGameplayTagContainer& AssetTags);   // was (ASC, FGameplayEffectSpec, Handle)
```

### 12. Meteorite C++ prep for the WaitInputRelease graph

`ChargeTime` is now `BlueprintReadWrite` and `MaxChargeTime` is
`BlueprintReadOnly` (Category "Charge"), so the new graph can write
`WaitInputRelease.TimeHeld` straight into `ChargeTime` before calling
`SpawnProjectile`. `SpawnProjectile` clamps to `[0, MaxChargeTime]` and the
double `SetSphereRadius` call (first with raw seconds, then with the ratio —
compounding the `Lerp`) is now a single call with the charge ratio. The old
timer path (`StartChargeTimeline`/`ChargeTick`/`CircleActorTick`/`bChargeEnded`)
is intentionally kept so the old graph nodes still work for comparison.

### 13. Blueprint changes (applied in-editor via MCP, 2026-07-13)

**Damage-type tags** (all compiled + saved):

| Blueprint | Before | After |
|---|---|---|
| `GA_ElectrocuteCourse` | `Abilities.Lightning.Electrocute` (0 damage) | `Damage.Lightning` |
| `GA_EnemyFireBolt` | *(none)* (0 damage) | `Damage.Fire` |
| `GA_RangedAttack` | *(none)* (0 damage) | `Damage.Physical` |

**GA_Meteorite — new WaitInputRelease implementation.** The old chain
(charge-timer + `Event CommitExecute` + gameplay events + per-tick
`TargetDataUnderMouse`) is **still in the event graph but disconnected** from
`Event ActivateAbility`, for visual comparison. The new chain (comment box
"NEW: WaitInputRelease refactor", at y≈2000):

```text
Event ActivateAbility
  → PlayMontageAndWait          (montage unset — same as the old node; set one if wanted)
      then          → WaitInputRelease
      OnInterrupted → End Ability
      OnCancelled   → End Ability
WaitInputRelease.OnRelease  → Set ChargeTime (from TimeHeld)
  → TargetDataUnderMouse
      ValidData → Commit Ability → SpawnProjectile → End Ability
      Data      → GetHitResultFromTargetData → BreakHitResult.Location
                                                → SpawnProjectile.ProjectileTargetLocation
```

`ChargeTime` (now `BlueprintReadWrite`) feeds `SpawnProjectile`, which clamps it
and scales damage by `ChargedMultiplier` and blast radius by
`ChargeTime/MaxChargeTime` (§12). `UMeteoriteProjectileSpell::InputReleased` no
longer commits the ability (the new graph commits itself; double-commit would
eat cost/cooldown early) — it only clears the old-flow charge timer. Applied
via Live Coding (patch); already in source for the next full build.

**Not carried into the new chain (was cosmetic, old nodes still show how):**
the red charge circle (`CircleActorTick`, driven by the C++ timer the new flow
doesn't start) and the release Niagara burst. Re-add as local-only cosmetics if
you miss them.
